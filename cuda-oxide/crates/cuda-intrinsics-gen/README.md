# cuda-intrinsics-gen

Extractor and deterministic source generator for cuda-oxide's intrinsics.

It reads `intrinsics/catalog.json` and writes every generated file in the
intrinsic pipeline. `MANAGED_GENERATED_ROOTS` in `src/generate.rs` lists the
ten directories it owns, where `generate` writes outputs and removes stale
marker-bearing files:

- `cuda-oxide/crates/cuda-intrinsics/src/generated/`: the raw intrinsic declarations;
- `cuda-oxide/crates/cuda-device/src/generated/`: the safe device wrapper modules;
- `cuda-oxide/crates/dialect-nvvm/src/ops/generated/`: the `dialect-nvvm` ops;
- `cuda-oxide/crates/mir-importer/src/translator/terminator/intrinsics/`: the importer
  dispatch arms that recognize each intrinsic by name (the enclosing
  `cuda-oxide/crates/mir-importer/src` is listed as a root of its own);
- one generated file each in `cuda-oxide/crates/cuda-oxide-codegen/src` (target
  requirements), `cuda-oxide/crates/mir-lower/src/convert` (conversion interfaces), and
  `cuda-oxide/crates/rustc-codegen-cuda/src` (collector predicates);
- `intrinsics/probes/`: the per-intrinsic PTX probe evidence.
- `intrinsics/generated/`: staged libm-to-libdevice mapping metadata.

Generated files carry a
`// @generated by cuda-intrinsics-gen ... DO NOT EDIT.` banner; edit the
catalog and regenerate instead.

```
cuda-intrinsics-gen extract --intrinsics-json FILE --nvptx-json FILE
cuda-intrinsics-gen extract --llvm-src DIR --llvm-tblgen FILE
cuda-intrinsics-gen generate
cuda-intrinsics-gen check
cuda-intrinsics-gen extract-libdevice --libdevice FILE --llvm-dis FILE
cuda-intrinsics-gen verify-libdevice --libdevice FILE --llvm-dis FILE
cuda-intrinsics-gen coverage [--family NAME]
cuda-intrinsics-gen check-abi-history --base-ref REF
cuda-intrinsics-gen probe [--all | --intrinsic ID] [--llc FILE] [--skip-terminal] [--per-target]
cuda-intrinsics-gen probe --candidate --intrinsic ID --llc FILE --gpu-target TARGET --ptx-feature FEATURE (--ptxas FILE | --skip-terminal)
```

Three of these gate CI (`unit-tests.yml`): `check` proves the committed
generated sources match what the generator produces, `probe --all --per-target`
checks the pinned `llc` identity and exact emitted PTX for every target declared
by each route, and
`check-abi-history` keeps the intrinsic ABI ledger append-only.

Generation shells out to `rustfmt`, which the pinned toolchain provides.

## Staged libdevice math family

`intrinsics/overlay/libdevice_math.toml` records the 72 existing f32/f64 libm
exports, including aliases and handwritten `fmin`/`fmax` and `sincos` routes.
The renderer emits `intrinsics/generated/libdevice_math.rs` and
`intrinsics/libdevice-math.md`. The Rust metadata is compiled by generator tests;
compiler dispatch and its handwritten tables are migrated in a subsequent PR.

This input is read explicitly by the libdevice family, separately from the
hardware shard index in `intrinsics/overlay.toml`. Its evidence comes from
`libdevice.10.bc`, so it does not receive hardware ABI IDs or change the hardware
catalog hash. The overlay reconciliation guard recognizes this separate reader;
unlisted hardware shards remain errors. Normal `generate` and `check` process
both domains, and stale metadata under `intrinsics/generated/` is reconciled.

Rows name a Rust signature class, optional libm aliases and cmath spelling,
placeholder suffixes, libdevice symbol, optional native LLVM alternative,
link classification, and optional `handwritten:NAME` handler. `{width}` expands
to `f32`/`f64`; `{suffix}` expands to `f`/the empty string. Unknown fields,
duplicate names, invalid templates, ambiguous ABI signatures, and incompatible
link classifications fail before outputs are written. Tuple signatures require
an explicit handwritten handler.

Generation checks every referenced C symbol and signature against the pinned
capture in `intrinsics/evidence/libdevice_math/cuda-13.0.json`. Capture provenance
and reproduction instructions are recorded beside it. The cache lets ordinary
`generate` and `check` run without a CUDA installation.

To verify the same ABI against a locally installed toolkit, use the pinned
toolchain's `llvm-tools` component:

```bash
libdevice_llvm_dis="$(rustc --print sysroot)/lib/rustlib/$(rustc -vV | sed -n 's/^host: //p')/bin/llvm-dis"
cargo run -p cuda-intrinsics-gen -- verify-libdevice \
  --libdevice "${CUDA_PATH:-/usr/local/cuda}/nvvm/libdevice/libdevice.10.bc" \
  --llvm-dis "$libdevice_llvm_dis"
```

Verification accepts compatible newer toolkit bitcode and reports its hash.
To refresh evidence, first review and update the bitcode hash pin in the shard,
then run `extract-libdevice` with the same arguments, followed by `generate` and
`check`. Extraction hashes and disassembles the same bytes, requires exported
definitions with exact return/argument types, and writes the capture only after
all referenced signatures pass.

Validation from `cuda-oxide/`:

```bash
cargo test -p cuda-intrinsics-gen --locked --all-targets
cargo clippy -p cuda-intrinsics-gen --locked --all-targets -- -D warnings
cargo run -p cuda-intrinsics-gen --locked -- check
```
